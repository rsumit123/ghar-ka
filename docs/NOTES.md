# Build notes (conventions for later phases)

## Backend conventions
- Add a router: `backend/app/routers/<name>.py` with `router = APIRouter(...)`, append to `ROUTERS` in `app/main.py` (mounted under `/api/v1`).
- `app/deps.py`: `DbDep`, `CurrentUser`, `get_optional_user`, `require_role(Role.x, ...)` (returns the User), `require_xhr_header` (multipart endpoints need `X-Requested-With: gharka`).
- Model changes: `uv run alembic revision --autogenerate -m ...` (batch mode); verify with `alembic check`.
- `app/db.py`: `UTCDateTime`, `str_enum()`, `utcnow()` (aware UTC). Naive datetimes are rejected.
- Tests: `tests/conftest.py` fixtures `db`, `client`, `sms` (`sms.last_code(phone)`), `make_user(Role.x, **fields)`, `login_as(user)`. UPLOAD_DIR is a temp dir. No network in tests (monkeypatch `httpx.get`).
- Admin actions always write AuditLog via `services.audit.write_audit(db, actor_id, action, entity, entity_id, details)` (caller commits). Vendor-scoped actions use `entity="vendor"`, `entity_id=vendor.id`, actions like `vendor.approve`, `vendor.fssai_update`, `vendor.override`, `fssai.docs_received`.

## Services added in Phase 2
- `services/images.py`: `save_upload(fileobj, *, subdir, private, allow_pdf=False) -> StoredFile(path, is_private, content_type)`; `process_image(bytes)`; `delete_stored(path, private)`; `resolve_path(path, private)` (traversal-safe); `UploadError(detail, status_code)`. Random-named `.jpg` (or `.pdf` for private docs). Paths are relative to `UPLOAD_DIR/public|private`; public ones are served at `/media/<path>`. Dish photos: `save_upload(..., subdir=f"v{vendor.id}", private=False)`.
- `services/golive.py`: `is_vendor_live(vendor, fssai, today)` and `live_vendor_filter(today)` (SQL expression on `Vendor`, EXISTS on FssaiRecord, no join needed; a test asserts both agree). Phase 3 listing: `select(Vendor).where(live_vendor_filter(local_today()))`.
- `services/clock.py`: `local_today()`. `services/vendors.py`: `get_vendor_for_user`, `missing_docs`, `vendor_is_live`, `media_out`, `advance_docs_if_complete`. `services/audit.py`: `write_audit`.
- `services/geo.py`: `search(db, q)`, `reverse(db, lat, lng)`; `MIN_INTERVAL_S` global throttle (0 in tests); `GeoError` -> 502. GeocodeCache keys: `s:<normalised q>#<i>` (one row per search result) and `r:<lat4>,<lng4>`. No schema change.

## API notes
- `GET /vendor/me` returns 200 `{onboarded:false, phone}` when not onboarded (not 404). Otherwise profile, `review_status`, `review_note`, `is_live`, `fssai`, `media` (private media have `path: null`), `docs_complete`, `missing_docs`.
- Media kinds: `profile` (replaces previous), `kitchen` (max 6), `id_proof|address_proof|passport_photo` (private, one per kind, replaced on re-upload, PDF allowed). `dish` is rejected on `/vendor/media` (menu endpoints will handle it).
- Rejected vendors: `POST /vendor/resubmit` or any `PUT /vendor/profile` sets status back to `pending`.
- Admin: approve (from pending/rejected), reject (note required), suspend (deletes vendor sessions), unsuspend (-> approved if ever approved else pending). Override needs reason >= 5 chars. `GET /admin/audit?page=&page_size=&entity=&entity_id=`. `GET /admin/media/{id}` serves private files (admin only, no-store). Dashboard keys: active_vendors, live_vendors, pending_vendors, fssai_expiring_60d, orders_today, orders_this_week, repeat_customer_rate (order ones are 0 until Phase 4).
- Admin media URL: `${brand.apiUrl}/api/v1/admin/media/<id>`; `<img>` works because the cookie is same-site.

## Frontend
- `@gharka/ui` additions: `Modal({open,onClose,title})`, `Switch({checked,onChange,label,hint})`. i18n keys are camelCase, grouped by comments in `i18n.ts`. Admin UI is English-only plain strings.
- Vendor app: `lib/useVendor.tsx` (`VendorProvider`/`useVendor()` -> `{me, reload, setMe}` wraps vendor routes), `lib/upload.ts` (`uploadWithProgress`), `lib/types.ts`, `lib/adminTypes.ts`, `lib/format.ts`; components `components/vendor/{UploadTile,KitchenPhotos,DocCards,Steps}`, `components/admin/{AdminLayout,bits}`. `/` -> `VendorEntry` (onboarding / status / home tiles). `/orders`, `/menu`, `/plans` and admin Orders/Complaints are placeholders for Phases 3/4.
- Local: `cd backend && uv run alembic upgrade head`, `uv run python -m app.cli create-admin ...`, `npm run dev`. Map tiles/marker icons need internet.

## Phase 3 (menus, discovery, orders)
- Clock: all "now" goes through `services/clock.now()` (callers must use `clock.now()`, not `from ... import now`). Tests: `clk` fixture freezes to 08:00 IST 2026-10-20 (`clk.set/advance`). Cutoffs: `clock.cutoff_for(date, slot, preset, cutoff_time)`; presets `1h|2h|3h|night_before_9pm|morning_10am`, default `2h`; `cutoff_at` is stored absolute. `slot_rank()` orders lunch before dinner (never ORDER BY slot).
- Offerings (`routers/menu.py`, `services/menu.py`): POST creates one per date (all-or-nothing; past dates / already-passed cutoffs = 422). PUT can't go below sold (409, atomic). DELETE returns 409 if any non-cancelled order includes the dish: the cook should "close" it via PUT `portions_total = portions_sold`. Photos: `POST vendor/offerings/{id}/photo` (stored as `photo_path`, no VendorMedia row; files shared by copies are deleted only when unreferenced). `copy` keeps local cutoff time and days-before; skips duplicates, past dates, passed cutoffs (returns `skipped`).
- Orders (`services/orders.py`): `place_order(db, customer, payload, now)`; capacity = one conditional UPDATE per dish (also requires unchanged price), rollback on any failure; `TRANSITIONS` + `change_status` (optimistic status UPDATE so a double cancel can't double-release). Portions released on cancel only if cutoff not passed. COD order becomes `paid` on complete. Pickup address shown to customer only after accept. Errors: 409 availability/state, 422 validation/fulfilment, 404 unknown. `orders.note` column (migration fe5f0320ed57). `PUT /me` (alias `/auth/me`). Razorpay is rejected until Phase 5 (hooks: `place_order` start, `PaymentOptions` in customer Checkout).
- Public: `GET /vendors` (needs lat+lng, locality_id or pincode; plain list; hyperlocal = same pincode/locality OR within max(delivery radius, `PUBLIC_SEARCH_RADIUS_KM`=5)); `GET /vendors/{id}?date&slot&lat&lng`. Phase 4 hook: call `materialize_subscription_orders` in `vendor_orders.list_orders`.
- Frontend: leaflet components moved out of the `@gharka/ui` barrel to `@gharka/ui/maps` (customer lazy-loads via `components/LazyMaps.tsx`; main chunk has no leaflet). `DietMark` lives in ui. Customer: `lib/{place,cart,store,format}.ts` (localStorage in try/catch); routes `/ /cook/:id /cart /checkout /orders /orders/:id /profile`. Vendor: Menu (`components/menu/AddDishSheet`), Orders (30s polling), `VendorTabs`, `DateStrip`. `VITE_TIMEZONE` added.
- Pitfall: a pydantic field named `date` annotated `date` breaks; use `import datetime as dt`.

## Phase 4 (tiffins, reviews, complaints, admin orders)
- Migration 9c1b1afa5c6d adds `subscriptions.lat/lng` (delivery pin, copied to materialised orders).
- `services/subscriptions.py` holds all subscription rules (see module docstring). Meal dates = start_date .. +weeks*7-1 on plan weekdays; cutoff = slot start - `plan.cutoff_hours_before` (APP_TIMEZONE). `paused_until` = first day meals resume (None = indefinite). API `status` is effective: active|paused|cancelled|finished.
- `materialize_subscription_orders(db, until_date, vendor_id=None, *, customer_id=None, subscription_id=None) -> created count`: creates `placed`, COD orders (price = price_per_week // len(days), item offering_id None) for meals whose cutoff has passed; skips skipped/paused/cancelled; commits per order and swallows IntegrityError on the unique (subscription_id, date) index. Called from vendor `GET vendor/orders`, customer `GET orders`, `GET subscriptions` (until = today+1) and `python -m app.cli materialize [--days-ahead N]`. Pause/cancel materialise first; resume turns past-cutoff un-ordered meals into skips so paused meals never reappear.
- Deactivating a plan hides it and blocks new subscribers only; existing subscriptions continue. Price/cutoff edits affect meals not yet materialised.
- Skip/unskip: 422 if not a meal day in range, 409 after cutoff; skip is idempotent. Subscription orders can't be customer-cancelled; vendors can cancel them.
- Reviews: `POST orders/{id}/review` (404 other's order, 409 not completed or duplicate). Customer order JSON has `can_review`, `review`, `is_tiffin`, `subscription_id`; vendor order JSON has `is_tiffin`.
- Complaints: customer `POST/GET complaints` (admin_note hidden from customers). Admin `GET admin/complaints?status=` (+summary), `PUT admin/complaints/{id}` -> AuditLog `complaint.update`, entity `complaint`.
- `GET admin/orders` -> `{total,page,page_size,summary,items}` (summary ignores the status filter). Dashboard: cancelled orders excluded; week Mon..Sun local; `repeat_customer_rate` null when no completed orders; extra keys `active_subscriptions`, `open_complaints`, `orders_per_day`(14), `repeat_customers`, `customers_served`. `active_vendors` (approved) and `live_vendors` both kept.
- Frontend: customer `/tiffins` (5th bottom tab), `SubscribeSheet`, `ReportSheet`, `ReviewSection`; vendor `/plans` (`PlanSheet`, VendorTabs now 3 tabs); admin Orders/Complaints/Dashboard (`OrdersChart` inline SVG). Avoid the pause/play glyphs (missing in some fonts).
